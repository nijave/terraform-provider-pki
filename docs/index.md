# terraform-provider-pki

A Terraform/OpenTofu provider for running a private X.509 certificate authority
entirely in-process. No external CA service, no `openssl` binary, no `cfssl`
binary: every resource is self-contained and CA material is passed per-resource
as PEM strings.

## Requirements

- **OpenTofu >= 1.11** (the primary target and what CI tests) or Terraform >= 1.11.
  The floor is 1.11 because `pki_bundle`'s `password_wo` is a [write-only
  attribute](https://opentofu.org/docs/main/language/resources/syntax/#write-only-attributes),
  which requires 1.11+.
- Go >= 1.25 to build.

## Why this provider exists

`hashicorp/tls` cannot express several things a private CA needs. This provider
closes those gaps:

| `hashicorp/tls` gap | What this provider adds |
| --- | --- |
| No arbitrary DN OIDs, no repeated OUs | `subject { attribute { oid = ... } }` and `extra_attribute`, in declaration order |
| Cannot set a certificate serial | `serial_number` (hex, normalized) |
| No `rfc822Name` / `IPAddress` / `URI` SANs | `san { dns_names, email_addresses, ip_addresses, uris }` |
| No PKCS#12 / PKCS#7 / JKS / DER bundles | `pki_bundle` with a write-only password |
| No CRL support | `pki_crl` |
| No per-extension criticality control | every extension block has `critical` |
| No `basicConstraints` `pathLen` | `basic_constraints { path_len }` |
